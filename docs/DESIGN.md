# laull-home

> 一个高度自定义、私有化的个人浏览器主页方案

## 简介

`laull-home` 是一个面向个人使用的、自托管浏览器主页。

它可以部署在自己的服务器上，并作为浏览器主页或新标签页入口使用。项目重点不是做一个传统的“网址导航”，而是提供一个可长期扩展的个人 Web Portal：统一管理书签、搜索、主题、背景、状态卡片和私人微服务，并让所有设备访问同一份服务端数据。

项目默认以**单用户私人部署**为主要场景，优先考虑：

- 使用体验简单；
- 页面高度可定制；
- 所有数据由自己掌控；
- 多端天然同步；
- 微服务易接入；
- 主题和功能模块能够持续扩展；
- 部署和升级尽量简单。

## 功能特点

### 高度自定义

支持自由配置：

- 主页布局；
- 书签分组与排序；
- 自定义图标；
- 搜索引擎；
- 搜索 Bang / 快捷命令；
- Widget 卡片；
- 背景图片；
- 主题；
- CSS 覆盖；
- 微服务模块。

主页不应依赖固定布局，书签和 Widget 都应支持在浏览器页面中直接编辑。

### 隐私保护

所有核心数据均保存在自己的服务器中，包括：

- 用户配置；
- 书签；
- 布局；
- 主题；
- 背景；
- Widget 配置；
- 微服务连接信息。

项目不依赖浏览器厂商账号同步，也不要求第三方云服务保存个人数据。

### 多端同步

`laull-home` 本身就是一个 Web 应用。

只要访问同一个地址：

```text
https://home.example.com
```

手机、平板、Windows、macOS、Linux 等设备即可直接读取服务器上的同一份数据。

例如：

```text
Mac 添加书签
    ↓
写入服务器数据库
    ↓
Windows / 手机刷新后立即可见
```

后续可通过 SSE 实现打开页面之间的实时同步。

### 私人微服务入口

主页可以作为个人服务的统一入口，例如：

- LTrade；
- 服务器状态；
- OpenWrt；
- 下载器；
- Git 服务；
- HomeLab 服务；
- TODO；
- 私人 API；
- 其他 Bun / .NET / Rust 服务。

微服务可以以以下形式接入：

- 普通书签；
- 状态 Widget；
- API 数据卡片；
- Action 按钮；
- iframe；
- 完整 Web 应用入口。

# 技术栈

## 前端

- Vue.js
- Nuxt.js
- TypeScript

Nuxt 主要负责前端页面、组件组织、路由和构建。

前端不直接保存关键业务数据，服务器数据库是唯一真实数据源。

## 后端

- Bun
- Elysia
- SQLite

后端作为独立 API 服务运行。

Elysia 负责：

- 用户认证；
- Session；
- Bookmark CRUD；
- Theme 管理；
- Wallpaper 管理；
- Widget 管理；
- Integration 管理；
- Secret 管理；
- 微服务代理；
- SSE；
- 导入导出；
- 健康检查。

SQLite 用于存储所有个人配置与状态。

## 部署

- Docker
- Docker Compose
- Nginx / Caddy

推荐生产架构：

```text
Internet / Tailscale
        ↓
   Nginx / Caddy
        ↓
┌────────────────────┐
│     laull-home     │
│                    │
│ Nuxt Frontend      │

          │
```

## 5. 组件系统

主页将所有界面要素收拢为组件节点（Component Node）。搜索条、书签、文件夹、图表卡片与微服务面板均以组件形式存在于桌面网格中。

### 1. 单 1x1 图标链接小书签

小书签占用 1x1 窗格，呈现类似手机桌面 App 的按钮触感：

- 视觉：居中展示高清图标（Favicon 或 Apple-touch-icon），底部或悬浮展示单行标题；缺失图标时显示首字母纯色胶囊；
- 交互：鼠标悬停微上浮 2px，按下回弹，点击直接在新标签页或当前页跳转目标 URL；
- 编辑行为：悬浮显示编辑与删除按钮，拖拽覆盖到相邻小书签时自动聚合为新文件夹。

### 2. 文件夹组件

文件夹收纳多个小书签，提供三种自适应形态：

- 1x1 紧凑形态：卡片内平铺展示 2x2 四宫格微型图标预览；点击弹出毛玻璃大浮层展开窗，列出内部全部书签并支持滑动翻页；
- 2x2 展开形态：卡片表面直接平铺渲染前 4 至 9 个小书签，右下角带有剩余数量标记（如“+5”），支持滚轮翻动查看其余书签；
- 3x3 大展板形态：直接平铺展示 9 至 16 个书签，顶部集成即时搜索过滤框，快速筛选目标网址。

用户在编辑模式点击尺寸药丸，可在 1x1、2x2、3x3 之间切换，内部书签数据保持完整。

```text
┌──────────┐  ┌────────────────────┐  ┌──────────────────────────────┐
│ [G]  [V] │  │ [G] GitHub  [V] V2 │  │ 常用分类           [🔍 过滤] │
│ [B]  [M] │  │ [B] Bili    [M] MDN│  │ ┌────┐ ┌────┐ ┌────┐ ┌────┐  │
│ 常用 (+5)│  │ [T] 推特    ... +3 │  │ │ G  │ │ V  │ │ B  │ │ M  │  │
└──────────┘  └────────────────────┘  └──────────────────────────────┘
 1x1 紧凑文件夹      2x2 展开文件夹                  3x3 大展板
```

### 3. 搜索框组件（1xn 弹性形态）

搜索框固定占用 1 个窗格高度，宽度根据需要设为 1x2、1x4、1x6 或自适应通栏（1xn）：

- 界面组成：左侧展示活动搜索引擎图标与下拉箭头，点击展开平铺选择面板；中间为输入区；右侧配置清空按钮与回车指示；
- 智能跳转：直接输入完整域名时按网址直接打开；输入以叹号开头的 Bang 指令时切换搜索源；
- 尺寸降级：1x2 紧凑模式下隐藏右侧按钮，只保留图标与输入框；1x4 及以上展开常用引擎快捷药丸。

### 4. 高度自定义卡片组件

卡片组件提供 2x2、3x3、2x3 与 3x2 等规格，支持自由装配视图与接入外部数据：

- 内容呈现：混合编排折线图、柱状图、环形进度、大字号等宽指标数值、Markdown 说明文本与单张封面图；
- 自定义 API 数据驱动：在卡片配置中直接填写外部 HTTP/HTTPS API 地址、请求方法、Headers 与定时轮询间隔（秒/分）；
- 数据路径解析：输入简单的 JSON 字段路径（如 res.data.current_price 或 stats.cpu），系统提取数值并自动绑定到卡片图表或指标文案中；
- 安全代理：外部 API 请求由后端服务统一代理转发，保护鉴权 Token，并阻断对内网非法地址的访问。

```text
┌───────────────────────────┐  ┌───────────────────────────┐
│ 外汇汇率监控        [API] │  │ 个人资产组合         [API]│
│ USD / CNY         7.2341  │  │ 72,430.00         +3.4%   │
│ ▃▅▇█▇▆▅▄▃ 24h 走势        │  │ █股票 45%  █现金 55%      │
└───────────────────────────┘  └───────────────────────────┘
 2x2 API 数据卡片               2x3 竖向组合卡片
```

### 5. 基于卡片组件的预制组件库

系统内置一系列就绪的卡片型预制构件：

- 日历卡片：月历网格，当天醒目反色高亮，支持标记日程事件点与农历换算；
- 时钟卡片：提供极简数字时钟、拟物翻页时钟、模拟刻度指针表盘与多时区世界时间；
- 天气卡片：展示当前气温与天气状态图示，附带 24 小时气温折线走势图；
- 股票与行情卡片：录入股票或加密资产代码，展示最新价格、日内涨跌幅与分时微型走势折线；
- 数据指标看板：针对主机与微服务，展示 CPU、内存、存储与网络速率仪表盘。

### 6. 组件 UI 定制与独立 Scoped CSS

每个组件支持细致的外观调节与独立样式覆盖：

- UI 外观配置面板：调节卡片背景半透明度、毛玻璃模糊半径（Blur）、边框粗细与圆角大小、内间距与文本对齐方式；
- 独立 Scoped CSS 定义：每个组件拥有一份独立的 CSS 文本。前端渲染时为组件分配唯一的属性选择器（如 .lh-widget[data-widget-id="w_101"]），将用户样式限定在组件内部，不污染其他组件与全局布局；
- 就地编写与实时生效：在编辑模式中直接打开卡片的 CSS 编辑抽屉，修改代码后页面立即热重载呈现新样式。

### 7. 组件克隆与自定义模板注册

- 一键克隆复制：点击组件工具栏的“复制”按钮，深拷贝当前组件的所有尺寸、API 绑定、UI 配置与独立 CSS，并在相邻空闲窗格生成新卡片；
- 注册为个人模板：将配置好的卡片保存为自定义模板。保存后该组件出现在组件库抽屉的“我的模板”分类中，供不同空间随时拉取复用。

### 8. 与主题系统的深度融合

所有组件均使用统一的全局主题变量（Theme Tokens）：

- 卡片底色使用 var(--lh-surface) 与 var(--lh-surface-hover)；
- 边框使用 var(--lh-border) 与 var(--lh-border-hover)；
- 文字使用 var(--lh-text) 与 var(--lh-text-secondary)；
- 强调色与图表高亮使用 var(--lh-accent) 与 var(--lh-accent-text)。

用户切换浅色、深色模式或更换主题风格时，所有组件自动平滑过渡，不需要针对明暗两套配色重复编写 CSS。组件的 Scoped CSS 也可以直接调用这些主题变量保持整体视觉协调。

### 9. 同尺寸组件叠放（Widget Stack）

相同尺寸的组件支持相互拖拽堆叠，形成多层叠放卡片：

- 堆叠操作：在编辑模式下，将一个 2x2 卡片直接拖放至另一个 2x2 卡片上方，系统自动将其转换为叠放组件池；
- 切换交互：卡片右侧或底部显现微小的分页圆点指示器；浏览模式下支持使用鼠标滚轮上下滚动、触控板双指滑动或手指上下轻扫轮播切换不同卡片；
- 编辑与拆分：编辑模式下展开层级管理器，支持调整各卡片的上下叠放顺序，或将特定卡片拖拽抽出还原为独立网格窗格。

```text
┌───────────────────────────┐
│ 21°C 晴             北京  │● (当前: 天气)
│ 体感 20°C   湿度 45%      │○ (下一层: 汇率走势)
│ [☀] 今日空气质量优         │○ (底层: 待办清单)
└───────────────────────────┘
 2x2 叠放组件（滚轮滑动切换）
```

### 10. 页面休眠与可见性唤醒（Page Visibility）

针对长久挂在浏览器后台标签页的使用场景，组件数据引擎对接浏览器的 Page Visibility 接口：

- 后台休眠：用户切换到其他标签页或最小化浏览器窗口（document.visibilityState === "hidden"）时，系统挂起所有卡片的 API 定时轮询，降低本地 CPU 开销与服务端网络请求；
- 切回唤醒：当用户重新激活主页标签页（visibilitychange 事件触发）时，系统比对上次刷新时间戳，对过期的卡片统一发出一次静默数据拉取，及时刷新展示内容。

### 11. 键盘盲操与全局快捷跳转

针对桌面端重度键盘用户，组件系统提供免鼠标快捷导航：

- 快速聚焦搜索：在非输入态下按下 / 键，光标立即激活主搜索框并选中文本；
- 快捷数字直达：按住 Alt 或 Option 键，前 9 个固定小书签右上角浮现微小数字角标（1 到 9），按下对应数字键直接打开目标链接；
- 拼音与字符速查：桌面处于非聚焦状态时直接敲击字母（如敲击 gh），页面呼出快速筛选框并实时匹配聚焦到对应书签。

### 12. 单卡片配置代码串导出与导入

卡片包含 API 映射与 Scoped CSS，具备完整的独立数据结构：

- 配置代码串导出：点击卡片配置面板的“导出配置”，系统将该卡片的尺寸、API 绑定、解析规则、UI 参数与独立 CSS 序列化并压缩为轻量 Base64 文本代码串，方便用户备份或在不同设备与空间之间搬运；
- 代码串导入：在组件库抽屉点击“导入代码串”，粘贴配置文本即可立即校验并在网格中实例化全新卡片，便于卡片模板的交流与复用。

# 微服务接入系统

## 设计原则

私人微服务不直接控制主页 UI。

微服务提供：

```text
数据
动作
描述信息
```

`laull-home` 负责：

```text
认证
代理
渲染
布局
主题
```

因此：

> 微服务输出数据与动作，主页决定如何展示。

---

## Integration

每个外部服务在 `laull-home` 中保存为一个 Integration。

例如：

```json
{
  "name": "LTrade",
  "slug": "ltrade",
  "baseUrl": "http://ltrade:8080",
  "authType": "bearer"
}
```

真实 Token 不返回浏览器。

请求过程：

```text
Browser
   ↓
laull-home API
   ↓
Elysia Integration Proxy
   ↓
添加认证信息
   ↓
Docker Private Network
   ↓
LTrade
```

---

# 主题系统

主题系统采用三层分级架构，解耦质感与色彩，支持按单主色自动推导，并提供全格式配置代码串导入导出。

## 1. 三层 Token 架构

变量体系由下至上分为三个层级：

1. 原始色板基准值（Primitives）：定义最底层的固定色彩刻度，如石板灰度刻度、海青绿度刻度与琥珀金阶梯；
2. 全局语义变量（Semantic Tokens）：统领全站外观意图，组件通过语义变量读取系统外观状态：
   - `--lh-surface`、`--lh-surface-hover`：卡片背景与悬停层；
   - `--lh-text`、`--lh-text-secondary`、`--lh-text-muted`：文字主次层级；
   - `--lh-accent`、`--lh-accent-hover`、`--lh-accent-text`：交互高亮；
   - `--lh-border`、`--lh-border-hover`：分割线与卡片边框；
   - `--lh-radius-sm` 至 `--lh-radius-lg`：基础圆角。
3. 组件局部变量（Component Tokens）：每个卡片内部使用 `--widget-bg`、`--widget-text`、`--widget-border` 等。组件默认将它们映射到对应的全局语义变量。如果单个组件需要自定义外观（例如亮黄色便签或深红色监控卡），直接在组件 Scoped CSS 中修改这组局部变量即可，不影响全局其他组件。

## 2. 玻璃质感与色彩解耦

系统将毛玻璃物理属性从具体的颜色值中抽离，作为独立的外观调节项：

- 卡片不透明度（`--lh-surface-opacity`）：支持在 50% 到 100% 之间滑动调节；
- 卡片磨砂模糊度（`--lh-surface-blur`）：支持在 0px 到 30px 之间微调。

用户可以根据个人喜好，在同一套色彩主题下选择纯实色无透光风格、轻微半透质感，或高通透的高斯模糊磨砂效果。

## 3. 种子色自动推导主题（Seed Color）

系统支持通过单个主色自动生成完整主题：

用户在调色板中挑选一个喜欢的强调色（例如冷杉青、紫藤罗或暖琥珀），生成算法自动推导对应浅色与深色两种模式下的卡片底色、边框浅色与阴影深度，并通过对比度公式自动选取符合 WCAG AA 标准的文本文字颜色。用户轻点一次即可获得一套协调完整的个人主题。

## 4. 主题代码串导出与导入

主题配置脱离单纯的前端写死代码，支持保存在用户设置中：

- 主题配置串导出：支持将当前主题的所有变量、不透明度与模糊度打包压缩为一段 JSON 格式的代码串；
- 快速导入与分享：粘贴配置代码串即可直接应用新主题，也可以直接导出给其他设备使用。

## 5. CSS 覆盖优先级

系统保留最高优先级的自定义 CSS 注入机制：

```text
全局基准变量 (Primitives)
   ↓
预设主题语义变量 (Theme Semantic Tokens)
   ↓
卡片局部覆盖变量 (Widget Scoped Tokens)
   ↓
用户全局自定义 CSS (User Custom CSS)
```

用户自定义 CSS 享有最高级联权重，前端通过 `<style id="lh-custom-css">` 注入文档头部。

## 微窗格响应式网格锚点

主页布局建立在微窗格网格之上。网格以统一的基础单元格（Cell Unit，基准宽高约 96px）作为空间对齐的锚点。

### 断点与列数划分

网格根据屏幕宽度自适应列数：

1. 宽屏与大显示器（宽度 >= 1440px）：12 列窗格；
2. 常规桌面与笔记本（宽度 >= 1024px）：8 至 10 列窗格；
3. 平板设备（宽度 >= 640px）：6 列窗格；
4. 移动端手机（宽度 < 640px）：4 列窗格，单元格基准尺寸缩减至 76px 左右。

### 多端布局同步策略

桌面端与移动端之间由于列数差异显著，系统支持两种排布同步模式：

1. 独立断点排布：桌面端与移动端分别存储独立网格坐标，用户在手机端调整位置不影响桌面端，在桌面端编辑不影响移动端；
2. 移动端流式降级模式：移动端不强行对齐桌面端的绝对坐标，直接按照桌面端组件的先后顺序降级为单向流动网格排版，组件宽度自动自适应移动端 2 列或 4 列满宽，免除在小屏幕上反复重复编排。

### 组件大小梯队

组件库提供多种尺寸规格，占用不同数量的窗格：

1. 1x1 窗格：单个书签图标、微服务指示灯、极简天气温度气泡；
2. 2x1 窗格：快捷胶囊、紧凑搜索栏、单行时钟日期、开关按钮组；
3. 2x2 窗格：方形卡片、书签九宫格托盘、便签备忘卡、单主机资源监视器；
4. 4x1 窗格：横向状态条、宽幅输入框；
5. 4x2 窗格：多引擎全功能搜索中枢、书签分类展开托盘、微服务走势图、待办清单；
6. 4x3 与 6x4 窗格：iframe 嵌入页面、复合数据大看板。

## 组件固定与流式排布

画布上的组件拥有两种定位属性：

### 固定锚点组件（Pinned）

用户可将特定组件（例如主搜索栏或顶部状态条）锁定在网格的特定行、列位置。固定后的组件优先占据指定窗格，周围其他组件环绕避让，屏幕尺寸变动时固定锚点保持在指定相对位置。

### 自由流动组件（Flowing）

未固定的组件遵循网格稠密排布规则（Dense Grid Flow）。系统计算网格空闲单元，按顺序将组件填入符合尺寸的空位，减少桌面空隙。

## 宽高变化自适应机制

当用户缩放浏览器窗口或在不同设备上打开主页时，布局通过三重规则进行平滑适配：

### 1. 自动换行

屏幕列数减少或当前行剩余单元格不足以容纳组件宽度时，网格引擎将组件沉降至下一行可用空位，避免内容溢出裁剪。

### 2. 窗格弹性缩放

单元格采用 `minmax(76px, 1fr)` 约束。在同一断点区间内（例如 1024px 到 1366px），窗格跟随容器宽度在一定比例内略微变大或变小，填满整行宽度，不留多余边距白边。

### 3. 组件内部形态自适应与自动折叠

组件内部通过 CSS 容器查询（Container Queries）监听自身宽高，在窗格被压缩或尺寸降级时自动折叠次要内容：

1. 搜索组件：空间充足时平铺展开常用搜索引擎图标与快捷 Bang；宽度受限时自动折叠图标，仅显示主输入框与下拉选择器；
2. 书签托盘：横向空间压缩时，自动折叠超出数量的书签为“+N”浮动展开泡，保持卡片轮廓规整；
3. 监控卡片：高度或宽度受限时，自动折叠隐藏历史折线图走势，仅保留即时数值与状态指示点；
4. 便签组件：小窗格状态下折叠文本格式栏，正文超出时限制行高并启用平滑内部滚动。

# MCP 扩展系统（Model Context Protocol）

系统接入标准 Model Context Protocol（MCP），允许外部大语言模型客户端通过结构化工具安全读取并操控主页的页面 CSS、组件设置与桌面整体排布。

## 1. 协议库选型与传输层

为避免重复造轮子，系统采用 Anthropic 官方维护的标准 `@modelcontextprotocol/sdk`（TypeScript / Bun 原生支持），配合 `zod` 定义工具入参校验。

服务端提供两种传输通道：

1. 远程 SSE 传输通道（主要模式）：挂载于 Elysia 服务内部，暴露 `/api/v1/mcp/sse`（建立事件流）与 `/api/v1/mcp/messages`（接收客户端 JSON-RPC 消息），使用官方 `SSEServerTransport` 管理客户端会话；
2. 本地 Stdio 通道（桌面客户端模式）：提供 `bun run mcp` 启动命令，基于 `StdioServerTransport`，供 Claude Desktop、Cursor 等本地工具通过标准输入输出管道直连。

## 2. 鉴权 Key：唯一生成与单向刷新机制

外部模型调用 MCP 必须通过专属的 API 密钥校验：

### 唯一性与单向展示

用户在设置界面的“开发者与 MCP”模块中管理该密钥：

- 每个账号系统只维护 1 个有效 MCP 密钥；
- 密钥生成格式为统一前缀高熵随机文本（如 `lh_mcp_` 开头的 32 字节随机字符串）；
- 密钥仅在初次生成或点击刷新时在弹窗中完整展示一次明文，并提示用户立即复制；
- 离开或关闭弹窗后，界面永远只展示末尾 4 位字符掩码（如 `lh_mcp_••••••••9a2b`）与生成时间戳，无法反查完整明文。

### 单向刷新与安全哈希

- 遗忘密钥时，用户只能点击“刷新密钥”；
- 刷新操作在数据库单事务内完成：立即永久吊销旧密钥，签发并持久化新密钥；用户也可以点击“停用”彻底收回 MCP 权限；
- 数据库只存储密钥的 SHA-256 哈希值，服务端不保存明文；
- 远程客户端在请求头中携带 `Authorization: Bearer <mcp-key>`，服务端比对哈希通过后方可建立 MCP 会话。

## 3. MCP Tools 工具矩阵

系统通过 `@modelcontextprotocol/sdk` 注册以下结构化工具：

### 页面 CSS 与外观工具

1. `get_theme_and_css`：读取当前主题标识、三层 Token（调色板、表面透明度、模糊度）、壁纸遮罩滤镜（暗化度与模糊度）以及全局自定义 CSS；
2. `set_custom_css`：传入 CSS 样式文本，校验安全边界后覆盖更新全局自定义 CSS；
3. `set_theme`：切换主题预设，或传入种子色由算法推导全套明暗色彩后写入设置；
4. `set_wallpaper_backdrop`：传入暗化百分比（0 到 80）与模糊半径（0 到 24），微调壁纸遮罩层。

### 组件设置与生命周期工具

1. `list_widgets`：列出当前空间所有组件实例的元数据、类型、尺寸跨度、网格坐标、业务配置、UI 微调配置与独立 Scoped CSS；
2. `get_widget`：输入 `widgetId`，获取单个组件的完整配置快照；
3. `add_widget`：指定类型（如书签、文件夹、搜索框、自定义卡片、时钟、天气等）、尺寸跨度、初始配置及可选坐标，在画布添加新组件；
4. `update_widget`：修改组件的标题、业务参数（API 地址、JSON 路径）或 UI 参数（透明度、圆角、内间距）；
5. `set_widget_css`：为特定组件写入或修改独立 Scoped CSS，限制在组件属性选择器内生效；
6. `delete_widget`：输入 `widgetId`，从桌面移除组件并释放占用的窗格；
7. `clone_widget`：深拷贝指定组件的全部配置，在就近网格空位生成副本。

### 整体排布与窗格锚点工具

1. `get_layout`：传入断点名称（如 `desktop`），读取完整的网格列数与所有组件占用的窗格坐标；
2. `move_widget`：将指定组件平移至指定的网格行列起始位置；
3. `resize_widget`：改变指定组件的窗格占用跨度（colSpan 与 rowSpan）；
4. `pin_widget`：锁定或解锁组件的固定网格锚点；
5. `batch_update_layout`：传入排布矩阵数组，单事务批量重排整页组件。

### 组件模板工具

1. `list_widget_templates`：读取预制与用户保存的组件模板清单；
2. `save_widget_as_template`：将配置好的现有组件沉淀为个人模板，供日后拉取复用。

## 4. MCP 只读上下文与浏览器实时热重载

### 只读 Resource 暴露

系统暴露只读资源 `home://canvas/overview`。模型连接后可直接读取该资源，一次性获取主页整体的组件清单、坐标拓扑与主题状态，作为后续微调排布或编写 CSS 的上下文基础。

### 变更热重载闭环

外部模型通过 MCP 成功执行修改后，服务端立即向所有已连接的浏览器客户端广播 SSE 事件：

- 修改 CSS 触发 `theme.updated`；
- 增删改组件触发 `widget.updated`；
- 移动排布触发 `layout.updated`。

浏览器端接收事件后就地重读并局部重新渲染，用户无需手动刷新页面，即可实时看到桌面组件位置移动、尺寸伸缩或样式变更。

# 安全

项目虽然默认单用户，但因为通常会部署在公网，因此必须考虑基础安全。

## 必须保证

- 密码使用强哈希；
- Session 使用 HttpOnly Cookie；
- 全站 HTTPS；
- Secret 不进入浏览器；
- 防止任意开放代理；
- 防止 Integration SSRF；
- 防止 favicon 抓取 SSRF；
- Markdown / HTML Sanitization；
- API Mutation 做 Origin / CSRF 校验；
- 日志中隐藏 Token 和密码；
- 上传文件限制大小和类型；
- Theme ZIP 防止 Zip Slip；
- iframe 使用 Allowlist。

# 设计原则

项目长期遵循以下原则：

1. **服务器是唯一真实数据源。**
2. **主页不包含微服务业务逻辑。**
3. **微服务只提供数据和动作。**
4. **Integration 不允许任意 JavaScript 注入。**
5. **Theme 不允许执行 JavaScript。**
6. **Secret 永远只存在于后端。**
7. **优先解决个人使用体验，不为通用场景过度设计。**
8. **简单功能优先，复杂能力按实际需求逐步加入。**
