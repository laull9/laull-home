# 数据备份与恢复指南

本文档说明 `laull-home` 的数据库快照、附件归档、保留策略与恢复流程。

---

## 1. 数据库一致性快照

在生产运行环境中，SQLite 启用了 WAL（Write-Ahead Logging）日志模式。如果直接通过文件复制方式拷贝 `.db` 文件，很容易遗漏尚在 WAL 缓存中未刷盘的事务，或者因读写锁冲突导致备份文件损坏。

`laull-home` 采用 SQLite 原生 `VACUUM INTO` 命令在线生成数据库快照：
- 在事务提交一致的边界点生成独立的 SQLite 单文件；
- 自动合并全部 WAL 日志，导出的快照数据库不依赖任何外部 WAL 或 SHM 辅助文件；
- 支持在 API 运行服务期间在线触发，无需停止服务进程。

---

## 2. 附件归档与清单结构

备份系统将一致性数据库快照与 `data/` 目录下的持久化资产统一打包为 ZIP 格式归档。

归档包含内容：
- `data/laull-home.db`：一致性数据库快照；
- `data/icons/`：缓存的站点 favicon 图标文件；
- `data/wallpapers/`：本地上传并持久化的壁纸图片；
- `backup-manifest.json`：包含备份版本、生成时间戳、程序版本、迁移版本号以及所有文件 SHA-256 哈希清单。

---

## 3. 快照保留策略 (Retention Policy)

为了防止备份文件无界增长耗尽服务器磁盘，系统内建了多维度的自动保留修剪策略：
- **最大快照数量**：默认最多保留 7 份历史快照，超额时自动删除最旧快照；
- **最长保存周期**：默认清理创建时间超过 30 天的过期快照；
- **总存储配额**：默认快照目录总占用上限为 500MB，超过限额时顺序淘汰旧快照。

每次生成新快照时，系统自动执行上述保留规则清理旧文件。管理员也可通过 API 手动触发清理。

---

## 4. 默认脱敏导出与加密备份

系统支持两种备份与导出模式：

### 4.1 默认脱敏备份 (Sanitized Backup)
- **安全红线**：导出的数据库快照中清空 `integration_secrets` 表数据，排除微服务 Token、密码等敏感凭据。
- **适用场景**：日常备份、多设备间主页配置同步、或者向他人分享数据时，确保内部私有微服务凭据不泄露。
- **清单标记**：`secretsExcluded: true`, `encrypted: false`。

### 4.2 加密备份 (Encrypted Backup)
- **保护机制**：若用户需要完整包含微服务凭据，必须在创建时设定至少 8 位的备份密码。
- **加密算法**：基于用户密码与随机 16 字节加盐，通过 PBKDF2（100,000 次迭代）派生 256 位密钥，使用 AES-256-GCM 对整份 ZIP 归档进行对称加密并记录认证标签。
- **文件后缀**：以 `.enc` 为扩展名保存。

---

## 5. 密钥恢复流程与灾难还原

### 5.1 恢复演练机制
在执行物理覆盖还原前，必须通过演练流程验证备份包的完好性：
1. **解密验证**：针对加密归档，验证密码有效性与密文完整性标签；
2. **归档解析**：解压并核对文件 SHA-256 哈希；
3. **数据库完整性检查**：在独立沙箱中挂载数据库，运行 `PRAGMA integrity_check;`，确认未损坏；
4. **版本兼容校验**：读取快照内的 `schema_migrations` 表版本，如果快照版本高于当前运行程序的版本，则拒绝恢复，防止降级导致数据错乱。

### 5.2 离线停机恢复步骤
生产环境推荐在停机状态下执行恢复：

1. 停止当前运行的后端服务进程；
2. 在项目根目录执行恢复命令：
   ```bash
   # 演练校验模式（dry-run，不写入磁盘）
   bun scripts/restore.ts backups/backup_2026-09-19_v14.zip --dry-run

   # 真实恢复脱敏备份
   bun scripts/restore.ts backups/backup_2026-09-19_v14.zip

   # 恢复加密备份
   bun scripts/restore.ts backups/backup_2026-09-19_v14.enc --password=你的加密密码
   ```
3. 恢复完成后重新启动后端服务；
4. 若恢复的是脱敏备份，登录管理员账号，进入设置 -> 微服务页面，重新录入各微服务的 Token 或密码。
